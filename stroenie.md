# Строение

Часть кодекса agent-baza. Читай, когда дело в коде, данных или интерфейсе.

Проект: дели по смыслу, не по типу файлов · в каждой папке — точка входа (index/README) · имя говорит содержимое · глубже 3 уровней не вкладывай.
Программа: данные проектируй раньше кода · заработало → сделай правильно → ускоряй (неизмеренное не оптимизируй) · одной вещи — одно дело · меняй малым шагом и проверяй каждый.
Тесты — критерий готовности: сначала опиши тестами поведение и крайние случаи, потом пиши код · баг закрывай тестом, воспроизводящим сбой · тесты под код не подгоняй.
Данные: факт храни в одном месте, остальное — ссылки и вычисления · модель строй по предметной области, не по удобству кода · связывай явным ключом, не совпадением значений · схему меняй бережно, с миграциями: данные ценнее кода.
Интерфейс: без указаний по дизайну модель скатывается в шаблонные стили, а общее «без шаблонного вида» лишь меняет один шаблон на другой. Вкус задавай списком конкретных приёмов, которых избегать (кремовый фон, курсивные акценты в заголовках, нумерация «01/02/03», моноширинные подписи, кнопки-таблетки), и дописывай в него то, что всплыло в результате.
